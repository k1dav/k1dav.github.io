## What？

**BI 報表** 是一種用來視覺化展示資料的工具，能幫助使用者快速理解、分析資料中的趨勢或隱藏資訊。BI 是 Business Intelligence 的縮寫，主要目的是透過資料的整合、分析與呈現，協助企業在決策過程中做出更具洞察力的選擇。

舉例來說，如果你是一家零售公司的分析師，你可能需要了解不同地區的銷售表現。透過 BI 報表，你可以將銷售數字、客戶行為等資料視覺化，並用圖表或儀表板來直觀展示。

---

## Who？

BI 報表主要面向以下幾類使用者：

1. **商業分析師**：負責挖掘資料中的商業價值。
2. **管理層**：需要簡單易懂的報表支持戰略決策。
3. **技術人員（如 Data Engineer、Data Scientist）**：提供報表所需的基礎數據與模型。
4. **業務團隊成員**：了解特定領域績效並提出改善建議。

例如，一位 Data Scientist 可能會構建一個 [ETL](/docs/notes/etl) 流程，把原始資料整理成 BI 報表需要的格式；而管理層則會透過儀表板查看 KPI 表現。

---

## When？

BI 報表通常會在以下情境中使用：

1. **定期報告**：每周、每月或每季檢查關鍵績效指標（KPIs）。
2. **即時監控**：例如監控網站流量或銷售額。
3. **專案分析期間**：如市場調研或產品績效評估。
4. **突發狀況處理**：快速判斷問題根源，例如收入突然下降。

舉例來說，在季度結束時，財務部可能需要生成一個 BI 報表來匯總所有收入與成本，以供高層進行決策。

---

## Where？

BI 報表通常出現在以下架構位置：

- 前端部分：
  - 使用者通過 Web 或 App 界面查看報告，例如 Power BI 儀表板。
- 中間層：
  - 數據庫查詢執行後，由工具（如 Tableau Server）進行可視化轉換。
- 後端部分：
  - 資料儲存於 [Data Warehouse](/docs/notes/data-warehouse) 或 [Data Lake](/docs/notes/data-lake) 中，再由 ETL 流程提供給 BI 工具進一步處理。

以電商架構為例，客戶交易數據可能先存入 AWS Redshift，再透過 Power BI 提供報告呈現給使用者。

---

## Why？

BI 報表能解決以下問題：

1. 資料量大且複雜時難以理解。
2. 傳統 Excel 表單效率低、易出錯、不直觀。
3. 跨部門溝通困難，需要統一視角整合資訊。
4. 缺乏即時性，導致動態市場變化反應不敏捷。

例如，在零售環境下，各地區營收數據分散於不同系統中。如果缺乏 BI 工具，就無法快速匯總並比較不同地區的銷售績效，也難以發現潛在問題。

## How？

### 🛠️ 建立階段

建立 BI 報表通常包括以下流程：

1. **資料收集與清理**
   - 使用 ETL 工具（如 Apache Airflow 或 Talend）從不同來源提取原始資料。
   - 清理空值、重複值等異常情況。
   
2. **定義指標（Metrics）**
   - 根據業務需求設計 KPI，例如「月營收」、「客戶留存率」等指標。

3. **儲存至 Data Warehouse**
   - 常見工具包括 Snowflake、Google BigQuery 等，用於集中儲存已整理好的結構化資料。

4. **設計前端可視化**
   - 利用 Tableau 或 Power BI 設計儀表板及互動式圖形，比如折線圖、熱力圖等。

### 🔍 查詢階段

查詢階段分為以下步驟：

1. 使用 SQL 查詢 Data Warehouse 中相關資料，例如：
```sql
SELECT region, SUM(sales)
FROM sales_data
GROUP BY region;
```
   
2. 將查詢結果傳送至前端工具進行可視化處理，比如在 Power BI 中生成柱狀圖顯示各地區銷售額對比。

3. 即時更新：
   通過設定排程或即時串接 API，確保報告保持最新狀態，例如用 Python Flask 建立 RESTful API 接口供前端調用更新數據。

## 補充說明

### 🔧 關鍵技術工具

| 功能                | 常見工具                     |
|---------------------|------------------------------|
| 資料清理            | Apache Airflow, Talend       |
| 數據庫              | Snowflake, Google BigQuery   |
| 可視化設計          | Tableau, Power BI            |
| 即時更新            | Python Flask, RESTful API    |

### 📌 範例比較

| 技術/功能           | 傳統 Excel        | 現代 BI 工具          |
|---------------------|------------------|-----------------------|
| 圖形互動性          | 基本靜態         | 高度互動式             |
| 資料量處理能力      | 易受限制         | 支援大規模數據         |
| 即時性              | 手動更新         | 自動排程/即時串接      |

### 🧠 延伸／常見誤解

1. 誤解：以為所有可視化工具都是 BI 工具。  
   澄清：像 Google Sheets 只是基本可視化，而真正的 BI 工具有多維度分析及自動更新能力。

2. 誤解：BI 工具只適合大型企業。  
   澄清：其實中小型企業也能從簡單 KPI 儀表板中受益，只需根據需求選擇適合自己的工具規模即可，例如免費版 Tableau Public 就是一個不錯起點。
